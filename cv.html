01 Architecture & Systems Designed

Layer 0 — Typed Message Bus Python

Synchronous dispatch over a registry of named node handlers. Every message is typed on three axes — kind, direction and hop budget. Loop prevention is a TTL rather than a heuristic: the effective ceiling is min(bus.max_hops, msg.max_hops), so a node may tighten its own budget but can never grant itself more runway. Hardened by adversarial review that found and closed three real defects, including a silent-loss path disguised as successful delivery.

Direction Invariants Org chart as types

Only a packaged conclusion or a flagged terminal notice may travel upward through the tree; a question moving up is rejected by the transport itself. Escalation policy is compiled into the message type system instead of being requested in a prompt. Every failure mode — hops exceeded, direction violation, contract violation, unregistered target — emits a distinct terminal notice back to origin with its own counter.

The Output Contract Honesty as a schema

A frozen structure of stance, integer confidence 0–100, and two to three reasons, each tagged data or assumption. Conviction is derived, never claimed: if no reason is data-backed, the conclusion is forced to low-conviction regardless of the stated number. Oversize payloads are rejected rather than truncated, and a null payload raises "silence is not allowed."

The Triad Pattern Anti-groupthink

Two specialist lenses — one quantitative, one interpretive — deliberately non-overlapping and structurally sealed from one another so they cannot converge socially. A single pacemaker reconciles them, maps their agreement to a confidence figure, applies a release gate, and is the only voice out. Any lens reading unfavorable holds a veto, and a domain-specific honesty cap prevents a confident recommendation on modeled data.

Multi-Tenant White-Label Factory 14 verticals live

A tenant-agnostic engine in which one configuration file is the only swap point — brand, skin, vocabulary, rooms, roles and AI persona. Each tenant deploys as its own project with its own environment, so isolation happens at the platform boundary rather than through row-level filtering. Every API is environment-gated with graceful degradation, so a cold clone renders and demonstrates with zero credentials configured.

Programmatic Provisioning Text to business

A build pipeline that creates a repository, creates a hosting project and starts a fresh branded product end to end against the GitHub and Vercel APIs, driven from a visual front end where a vertical is chosen, branded and generated. SaaS tenant provisioning, operated by one person.

The Spine & Rooms Model Domain modeling

Each vertical is modeled around a single core domain object — a project, a listing, a show, a membership, a person — and every module page is a projection over that one record rather than a separate silo. Cross-room consistency becomes structural instead of synchronized, and adding a room stays additive and cheap.

Safety Enforced by Absence Learner products

Guarantees implemented as missing capability rather than instruction. There is no timer code, so a child cannot be raced; no error-red token, so failure cannot be rendered; no schema field where agent-authored prose could ride, plus an n-gram fence rejecting content words the child did not write. A rule expressible as configuration is one write from repeal; a rule that is structurally unrepresentable is not.

Runtime Truth Enforcement Agent receipts

A server-side guard that forces a real tool call and emits a receipt, so an agent cannot narrate work it did not perform. Paired with a resumable worker that recovers tasks stranded by function timeouts, and a cron heartbeat that lets seats pull from and push results to a shared task board.

Skins Engine Accessibility guard

02 Design, Brand & Naming

Design is not a layer applied at the end here; it is the third step and it sets the scheme. On every product the sequence is name, mark, icon — and only then code. The icon decides the palette, the weight, the personality and the vocabulary the software inherits, so making it early is a design decision about the whole system rather than a cosmetic one made late.

Naming the line. I named all fourteen vertical products — Abode, Buttress, Truss, Musical, 8mm, Amphitheater, LilNinja, 4barrel, Targeted, Stay@Home, Smiley, Sleeves, Toolbelt and Moments — along with the consumer families and their individual apps. When an earlier generation of names stopped fitting, I retired every one of them at once rather than letting two vocabularies coexist. The retirement is enforced rather than remembered: the canonical names live in a single source file, the rule that retired names never reappear is written into the engineering constitution, and a surviving instance of an old name is treated as a defect to fix, not a variant to tolerate. That is what keeps a brand consistent across fourteen pricing pages, fourteen showrooms and a storefront.

The identity. A single warm system — espresso to forest on a 120° gradient, gold for emphasis, cream for light surfaces, with a faint gold grid — replacing an earlier blue identity that was retired wholesale and archived rather than left to drift. One mark kit is the source for every surface; the correct variant for each background is specified rather than chosen by eye each time.

Icons as a build artifact. Each product's mark is authored as a master SVG by hand — no drawing tool — and compiled by a Python pipeline into a complete store kit: thirteen iOS sizes, Android adaptive foreground and background at every density with the 66% safe zone respected, the Play 512, and rendered QA proofs so the output is inspected rather than assumed. Roughly fifty files per product, reproducible from one source. The house style for app marks is deliberately flat and repeatable — dark tile, light inner panel, one bold stroke symbol, one accent dot, no gradients or shadows — so a new product looks like a member of the family on the day it ships. The kit is treated as mandatory, not optional: a missing apple-touch-icon causes iOS to screenshot the page and use that as the icon, which is a brand failure produced by an omission rather than a decision.

Design system and theming. Brand tokens rather than hardcoded values, documented components, and a portable theming engine that lets an entire hub be reskinned per tenant without forking the interface — the same mechanism that makes a white-label product viable. Every surface is judged phone-first at 402 pixels before anything else, because that is where these are actually used.

Motion built on physics. No linear easing anywhere; spring and ease-out curves, velocity-based fling on swipe, a haptic tick on commitment, correct overscroll behaviour, and prefers-reduced-motion honoured throughout. Motion is specified as a standard rather than improvised per screen, so interactions feel like one instrument rather than fourteen.

Accessibility, measured rather than claimed. The palette is audited against WCAG 2.1 AA contrast ratios rather than eyeballed, with results precomputed for the current brand colours. The audit currently records a known failure — one muted foreground token against the forest background — which is carried as an open finding instead of being quietly rounded up to compliant. Same rule as everywhere else in this record: the measurement is only useful if it is allowed to say no.

Illustration and character work. Mascots, characters and app illustration drawn as clean SVG, including work rebuilt from reference into production art. The working method is render-then-look — output the drawing, examine it, and correct it — because a character that reads as the wrong animal or lands in the uncanny middle cannot be diagnosed from the code alone.

Design decisions with commercial consequences. Replacing the sales deck with the product itself — every vertical opens as a live showroom running the real software on realistic data in the prospect's own browser — was a design call before it was a sales one. So was the choice to state limits inside the interface rather than in a footnote, and to build products that decline to display a value they cannot stand behind.

06 AEpsychograph — Household Segmentation Engine

The premise. Rebuild PRIZM-class household segmentation on free public government data, minus the license layer. Commercial comparables list between $1,645 per year and $1,500 per month.

The model. Forty-eight segments across four urbanization tiers, four affluence tiers and three lifestages; fourteen activities; eight psychographic types; indices computed as a segment's rate over the national average, times one hundred, clamped to a 20–320 band.

The sources. US Census American Community Survey five-year tables for income, households with own children, and 65-and-over; Bureau of Economic Analysis state personal consumption; Bureau of Labor Statistics Consumer Expenditure series, cached and refreshed on a thirty-day cycle.

The honesty constraint, enforced in code. Who a household is comes from real Census data; what they are likely to do is modeled — and the two are never allowed to blur. Without live Census data the pacemaker is hard-capped below the targeting threshold, making a confident targeting recommendation on modeled data arithmetically impossible rather than merely discouraged. Classifiers are required to return "unclassified" and "unassessable" rather than force a label.

07 AE Comply & IT System Health — Compliance Readiness and Infrastructure Monitoring

What it is. A monitoring platform that answers two questions for the same owner: is my infrastructure working? and can I prove it was? It runs credential-free checks against a business's public infrastructure on a schedule, rolls them up to a plain-language state, hands back the exact remediation, and seals every run into tamper-evident, dated evidence. Research, architecture, engine, front end, deployment and live verification of the first working version were completed in a single day; it was extended over the following day into the shipped product described here.

The engine — nine controls, zero credentials, zero dependencies. A Node serverless function evaluates, per domain: SPF (only authorized servers can send as the domain), DMARC (spoofed mail is reported and can be rejected), MX (mail routing resolves), MTA-STS (mail transport encryption is enforced, verified by fetching the policy file — the DNS record alone does nothing), TLS-RPT (transport failures are reported), TLS (certificate valid, protocol current, expiry counted in days), DNSSEC (the delegation is signed), CAA (only named authorities may issue certificates), and browser security headers (CSP, HSTS, nosniff, frame-options, referrer-policy). Every check is free and public. No customer credential is ever requested, held, or required.

Authoritative resolution, and why it exists. The engine does not trust a recursive resolver. For every domain it looks up the registered domain's own nameservers and queries those directly, labeling each result with its dns_source. This exists because the first build used a recursive resolver, received an empty TXT answer, and produced a false "no SPF record" finding against a domain that did have SPF. A recursive answer is hearsay; evidence comes from the authority. The bug was caught by checking output against a second source, the resolver was rewritten, and the incorrect evidence pack was formally marked void rather than quietly edited.

Three further classes of false failure, each found and eliminated. A compliance tool that reports a failure that isn't real is worse than no tool at all, so the applicability model became the product's central design problem rather than an edge case.
— Category errors. Application hosts such as *.vercel.app have no mail service and cannot send or receive; scoring them "no SPF, no DMARC, no MX" produced three red failures per client property for controls that do not exist there. Host-type detection now returns N/A, and the score reads passed-over-applicable rather than passed-over-total.
— Unanswerable queries. Node has no resolveDs, and DNSKEY is not a supported record type, so the first DNSSEC and CAA implementation reported "not signed" and "no CAA" for every domain tested, including Cloudflare's own — which is demonstrably signed and does publish CAA. Caught by testing against a known-good third party rather than only against my own estate. Both checks were moved to DNS-over-HTTPS against two independent resolvers, and an unanswerable query now returns UNKNOWN, never FAIL. Scoring "we could not check it" as a red X is fabrication by omission.
— Healthy things that look broken. An authenticated endpoint answering 401 is a working endpoint. Only a dead socket, a timeout or a 5xx is an outage. Scoring an auth gate as down would page a human on every single run.

The evidence vault — server-side by necessity. Each result is serialized deterministically and hashed with SHA-256 together with the previous entry's hash, forming an append-only chain in which any retroactive alteration invalidates every hash after it. Provable ordering and tamper-evidence without a paid notary or timestamping service. The chain is computed on the server, never in the browser — evidence a client calculates for itself is not evidence, because anything a client computes it can also fabricate. Storage degrades honestly: when the store is unreachable the response reports stored:false with a reason rather than presenting an unsaved run as sealed.

Framework packs, with the limits attached to the findings. Results can be read against HIPAA, home-care and insurance-audit mappings. Every pack carries a mandatory covers and doesNotCover statement that travels in the same payload as the findings, so the limits are structurally inseparable from the results. The HIPAA pack states in its own output that it does not address §164.308 administrative or §164.310 physical safeguards and is not a HIPAA risk assessment. A limitation in a footer can be screenshotted away; one inside the payload cannot.

Tenant isolation, and an honest account of its ceiling. Each customer holds a random twenty-four-character workspace key that scopes their evidence chain, history and watchlist — no account, no password, no personal data collected. Isolation was verified live rather than assumed: a second workspace was created and confirmed to see an empty genesis chain while the first held its own tip and history. The limit is stated plainly in the product's own privacy page: the object store on this account rejects private access outright, so stored objects are technically readable by anyone holding the URL. What protects a customer is that the URL contains their unguessable key — a capability, which is real protection, but is not an access-control list, and no page is permitted to describe it as one. Records hold domain names and check results only; real ACLs are a precondition of ever holding anything more sensitive.

Scheduled monitoring that actually monitors. The daily job walks every registered workspace watchlist, re-runs that customer's domains against their chosen framework, and seals the results into their chain. This is called out because the first version of the schedule checked only three hardcoded internal domains while the interface said "around-the-clock monitoring" — a promise the product did not keep. The gap was found by auditing my own marketing copy against my own cron job, and the interface was additionally corrected to say plainly that email alerting is not switched on yet, rather than implying a notification path that does not exist.

Observe-only, permanently — a business decision expressed as an architecture. The companion IT · System Health capability monitors service reachability, certificate expiry thresholded in days rather than booleans, and integration key status as booleans only, with key values never read or returned. It rolls up to CLEAR / WATCH / INTERVENE and produces a fix list where every entry carries what it means, what to do, and — where a literal value exists — the exact string to paste. It does not, and will not, remediate anything itself. Errors-and-omissions and cyber liability coverage was priced at roughly $245 per month and declined; the resulting rule is that Accelerated Experiences LLC does not take the keys to machines it does not already run. That boundary is written into the specification as a permanent product definition rather than a limitation to be engineered around later.

Validated against its own maker before being offered to anyone. Run across the full ten-domain company estate. It found real defects; every one was remediated and re-verified at the authoritative nameservers, taking DMARC coverage from three of ten domains to ten of ten and closing the estate with zero open findings. Two findings were deliberately left unremediated and documented as such — a monitor-only DMARC policy that should not be tightened before report data has been read, and a Content-Security-Policy whose incorrect deployment breaks a working storefront and requires a report-only observation period first. That policy was instead shipped in report-only mode with a collector endpoint written to read the raw request stream, because the platform does not body-parse the application/csp-report content type and the first version silently logged empty reports while appearing healthy. Knowing which findings not to fix immediately, and detecting a monitor that is quietly recording nothing, is the difference between a compliance tool and a liability.

Governance tooling built alongside it. The engineering constitution that governs this and every other system was given a self-verifying stamp and an automated consistency gate: a checker recomputes the document's hash, verifies article sequence, and compares the two independent copies. It caught a one-character divergence between them that every structural check had passed. The gate deliberately treats an unstamped document as a failure rather than a pass — an unverifiable constitution cannot be trusted, and the first version of my own gate had that backwards.

Two products killed on purpose. Compliance monitoring and IT health were built independently, in parallel, and found to overlap by roughly seventy percent while selling to the same captive audience. Rather than ship both, they were merged into one engine and one interface. The merged capability was then briefly specified as a paid fourth pricing tier across fourteen products — and that tier was cancelled before it shipped in favor of including it with each product's existing top plan, removing a pricing change across fourteen pages and eliminating an outlier where the flat uplift would have raised one product's price by ninety-one percent. The commercial argument became free tells you, paid proves it: operational health is visible to everyone because it costs nothing to run, and the sealed evidence is what the top tier contains.

Cost of goods: $0 recurring. DNS, TLS handshakes, HTTP response headers, DNS-over-HTTPS, and public control catalogs. Paid feeds were excluded rather than faked, and the interface declines to display any control it cannot honestly evaluate. The deployment ships with the exact security headers the product tells clients to add, so it passes its own audit.

Stated limits. External, credential-free checks only; authenticated posture integrations are specified and not built. Email alerting is not switched on. It is a readiness and evidence tool, not a certification body — it cannot issue an attestation, and neither can any competitor, since that requires a licensed CPA firm, but the distinction is stated in the product's own interface rather than buried. Incumbents in the adjacent category (Vanta, Drata, Secureframe, Sprinto) run $6,000–$28,000 per year and sell to venture-backed startups pursuing SOC 2; this sells to businesses facing county inspectors, insurance audits and HIPAA — dental, home care, telehealth, trades, engineering — where those incumbents do not compete and the deliverable is an organized binder rather than an auditor portal. It has no paying customers as of this writing: live, functional, validated and included in the product line, but not yet sold.

The defect found after launch, and why it matters. The room is served both at its own domain and, through a rewrite, under a path on the company store. The front end used absolute /api/ paths, which at the mounted location resolve to the store root — where only one of its three endpoints was mapped. The evidence vault returned 404, no tenant workspace was ever created, and every run came back unsealed while the interface reported "sealed in the vault." All nine checks rendered correctly the entire time, which is precisely why it survived a full day of testing: every prior verification had used the direct domain, where absolute paths resolve correctly. The sealed evidence is the entire commercial reason the top tier exists; at the public address, that half had never happened once. Fixed by resolving API calls against the page's own directory — required in any case for the product to run mounted inside a host application. My own first fix was wrong and was reverted rather than reconciled: it populated the displayed key from a second source that disagreed with the one the evidence sealed under, replacing an empty field with a confidently incorrect value. Of the two, showing the wrong answer is the worse failure, and it is the same error the engine's applicability model exists to prevent.

The record-keeping standard written off the back of it. Codified as a constitutional article: every project is logged in the company's own operating system at the start; scheduling is deliberately not required, because work here completes within a day across several parallel AI instances and dates would be noise — the requirement is the log, not the calendar. The log must state what was done and who did it, name every document produced, and close with a written brief covering what was built, what was decided and by whom, what broke, what remains open and what it cost. If a defect is found after the brief is filed, an addendum is filed against it rather than the original being quietly corrected — the same instinct as the hash chain: a record is only worth something if it cannot be rewritten to look better. The constitution itself carries a self-verifying checksum, and an automated gate confirms its three independent copies match.

08 AE Fraud Division — Sanctions Screening, Transaction Triage & Case Files for Community Banks

What it is. A fraud-protection suite for community banks and credit unions, built August 2026 and launching the same month. Three rooms with one job: SCREEN checks names against the live U.S. Treasury OFAC SDN and Consolidated lists; WATCH triages a transaction file against the classic fraud and laundering typologies; FILE promotes any alert into a case with its evidence chain and a SAR-style draft narrative, exported as a packet for the institution's own review. The incumbents (NICE Actimize, Verafin, Unit21, Featurespace) sell custom-quoted suites at $2,000–$15,000 per month behind 60–90-day core-system integrations; this takes the no-integration path — the bank drags a file into a browser — at a published flat price, never per-seat.

Every alert shows its work. SCREEN hits carry a match score, the matching route (name or listed alias), the exact list entry, and a link to verify that entry on the Treasury's own sanctions search. WATCH alerts cite the exact rows that triggered them — structuring kept under the $10,000 currency-reporting threshold inside a 7-day window, velocity spikes measured against the party's own median active day, round-dollar repeats, exact-amount duplicates within 3 days, dormant relationships waking up with a large movement, and new payees arriving straight into the file's 95th-percentile amounts. The release gate is written into the product: no citation, no alert.

The privacy architecture is the pitch. WATCH runs entirely in the bank's own browser — the transaction file is parsed (CSV or NACHA/ACH entry-detail records) and scored client-side and never transmitted or stored. The only data that leaves the machine is a name the user explicitly sends to the sanctions screen. For a two-person compliance shop, the security review answers itself.

Stated limits, in the product's own interface. A CLEAR is a screening result at a stated threshold, not a background check or legal determination; a HIT is a lead for a human, not an accusation. Case narratives are drafts — the institution's BSA officer reviews, decides and files. The typology engine catches the classic patterns and says so plainly rather than claiming behavioral learning it does not yet perform. When a sanctions list cannot be loaded, the product says which list and screens against the rest — it does not pretend. No paying customers as of this writing: built, launching, and priced — not yet sold.
